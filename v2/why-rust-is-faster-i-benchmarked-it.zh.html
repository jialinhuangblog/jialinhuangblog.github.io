Rust 比 Node 快多少？我量了七種情境

frontendrustbenchmarkperformancev8

我寫過一整篇，JavaScript build 工具被 Rust 一個一個換掉的血淚史，SWC 換掉 Babel，Turbopack 換掉 Webpack。那篇一直說 Rust 比較快，到底快多少？

就來跑跑看 benchmark 吧，都在同個環境。

七種情境，從 Node 快 16% 到 Rust 快 35 倍

Rust 對 Node 最多差到 35 倍左右。

一千萬個浮點數相加，Node 9.78ms、Rust 9.65ms，幾乎一樣。每一步都要等上一步加完（s = s + 這一筆），一次浮點加法大約 3 個 cycle，兩邊都停在這個速度，換語言也沒用。

大量配置用完就丟的小物件，Node 反而比較快，每一輪的中位數是 4.34ms，Rust 是 5.05ms。V8 的 generational GC 就是為這種情況設計的：新物件都放進一塊連續的記憶體（young generation），配置只要把指標往後移；放滿了就停下來，把少數還活著的搬走，剩下的整塊清掉。Rust 則是每個物件各自向 allocator 要記憶體，用完再一個一個還回去。

不過碰到 GC 停下來的那幾輪，Node 就變慢了。最慢的 1%（p99）Node 是 10.34ms，Rust 是 5.74ms。用 --trace-gc 跑一次，200 輪裡 GC 一共停了 275 次，最長的一次 4.29ms。

最右邊那個 35 倍，是把「每個數字乘二、過門檻就加總」寫成 map().filter()。Node 的 map 先產生一個一千萬筆的陣列，filter 再產生一個，整段要 578ms；同樣的事用手寫 for 迴圈只要 62ms。Rust 的 iterator 不產生中間陣列，每個數字從乘二、比門檻到加總一次做完，編譯出來跟手寫迴圈一樣，16.1ms。

小陣列 Node 快，大陣列 Rust 快

同一段 code，只改陣列長度。

資料是亂數，所以那個 if 大約一半成立。總工作量固定在讀兩億個元素，陣列越短就重複走越多遍，圖上畫的是每個元素花的時間。

陣列一長，Node 就變慢，Rust 不會，原因是兩邊把那個 if 編譯成不一樣的 machine code。

Node 留著分支。 CPU 不等比較結果出來，先照這個分支最近幾次的走向猜一條路往下跑，這叫 branch prediction。猜對沒有成本，猜錯就把那條路上算好的丟掉重來。圖上陣列從一千筆拉長到一百萬筆，Node 每個元素從 1.02ns 升到 5.59ns。另一組用一千萬筆的陣列，把條件換成幾乎永遠成立，讓 CPU 每次都猜對，Node 每個元素就從 6.26ns 降到 3.64ns，而 Rust 前後都是 1.57ns 左右。

Rust 沒有分支。 LLVM 把加了跟沒加的結果都先算好，再用 fcsel 這條二選一的指令挑一個。每個元素多算一次加法，但 CPU 沒有東西要猜。

SWC 說的 20 到 70 倍，有多少是 Rust 的功勞

SWC 宣稱單執行緒比 Babel 快 20 倍、四核心快 70 倍。

最接近 bundler 的那組，是建一棵 178 萬個節點的 AST（abstract syntax tree）再走訪一遍，Node 39.62ms、Rust 14.79ms，差 2.68 倍。語言本身就差這麼多，20 倍除以 2.7，還有大約 7 倍要另外找原因。

拿 Go 寫的 esbuild 來對照，它跟 SWC 一樣是原生執行檔、從頭設計，只是語言不是 Rust。

同一個 280KB 的檔案編譯成 ES2019，Babel 134ms，SWC 19.6ms，esbuild 25.6ms。每個工具各跑六次，esbuild 每次都比 SWC 慢兩到三成，但兩個都比 Babel 快五倍以上，這五倍不是 Rust 才有。

編譯成 ES5 的話，Babel 4385ms，SWC 78.1ms，差 56 倍。esbuild 不支援 ES5。

SWC 比 Babel 快的這兩個倍數，ES2019 的 6.8 倍跟 ES5 的 56 倍，各自除以語言的 2.7 倍，ES2019 還剩 2.5 倍，ES5 還剩 21 倍。剩下的這些倍數，是 Babel 跟 SWC 兩個程式寫法不同造成的。

70 倍裡的四核心，也不全是 Rust 的功勞。同一份工作開八個執行緒，Node 快 6.2 倍，Rust 快 7.6 倍。Rust 多拿了一點，但 Node 也快了六倍，用內建的 worker threads 就能把工作分給每個核心，Babel 只是沒用而已。

SWC 的倍數是怎麼組成的

  • 大約 3 倍，語言：從 JavaScript 換成編譯成原生執行檔的語言。AST 走訪是 2.7 倍；跑一次就結束的工作，例如讀一個 4.8MB 的檔、改寫後寫回，算上啟動是 2.7 到 3.7 倍，多出來的大多是 Node 的啟動時間，node -e 0 什麼都不做也要 34.8ms。
  • 2.5 到 21 倍，程式寫法：工作越重，這部分越大。目標從 ES2019 換成 ES5，Babel 的時間變成 33 倍，SWC 只變成 4 倍。
  • 大約 3.5 倍，多核心（SWC 自己的 70 除以 20）：Node 也有 worker threads，Babel 沒用。

只有第一項跟語言有關，而 Go 寫的 esbuild 也有這一項。
