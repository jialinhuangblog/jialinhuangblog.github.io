15:T7ac9,<p>There are four things you can configure in Claude Code: skills, agents, tools, hooks. Each lives in its own file, and with the right field one can start another. That gives sixteen combinations, and every one of them was run.</p>
<p>Environment:</p>
<ul>
<li>CLI 2.1.252</li>
<li>Agent SDK 0.3.252</li>
</ul>
<h2>The four</h2>
<h3>Tool</h3>
<p>A tool is a function the model can call. A name and a parameter schema, nothing else.</p>
<p>Names come in two shapes.</p>
<p>Built-ins are short: <code>Read</code>, <code>Write</code>, <code>Edit</code>, <code>Bash</code>, <code>Grep</code>, <code>Glob</code>, <code>WebFetch</code>, <code>WebSearch</code>.</p>
<p>MCP servers give you <code>mcp__&#x3C;server>__&#x3C;tool></code>, like <code>mcp__claude_ai_Jira__getJiraIssue</code>.</p>
<p>The difference only shows up when writing a hook matcher. To catch Bash, write <code>Bash</code>. To catch a whole MCP server, write <code>mcp__claude_ai_Jira__.*</code>, because without the trailing part the matcher hits nothing.</p>
<p>Here is my own local tool frequency, roughly. 87 session transcripts, 12,017 calls.</p>
<pre><code>  6388  Bash
  3384  Edit
  1129  Read
   585  Write
   181  WebSearch
   165  WebFetch
    43  Skill
    36  ToolSearch
    31  Agent
    27  AskUserQuestion
    25  Artifact
    12  mcp__claude-in-chrome__tabs_context_mcp
</code></pre>
<p>Bash alone is half of it. <code>Grep</code> and <code>Glob</code> are missing because I habitually use bash; one command chains <code>find</code>, <code>grep</code>, and <code>head</code>, where the built-in tools would be three separate calls.</p>
<p><code>Agent</code> and <code>Skill</code> are on the same list. Starting a subagent is the model calling a tool named <code>Agent</code>. Running a skill is the model calling one named <code>Skill</code>. Same shape as calling <code>Bash</code>, just with a bigger effect.</p>
<p>Which gives you one useful place to intervene. A <code>PreToolUse</code> hook with matcher <code>Agent</code> runs before every subagent launch, and it can deny the launch.</p>
<h3>Skill</h3>
<p>A skill is a <code>SKILL.md</code>. Frontmatter on top, instructions for the model below.</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="markdown" data-theme="github-dark github-light"><code data-language="markdown" data-theme="github-dark github-light" style="display: grid;"><span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-dark-font-weight:bold;--shiki-light:#005CC5;--shiki-light-font-weight:bold">---</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">name: hooktest</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">description: Test skill. Use when the user says hooktest.</span></span>
<span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-dark-font-weight:bold;--shiki-light:#005CC5;--shiki-light-font-weight:bold">---</span></span>
<span data-line=""> </span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">Call the Bash tool with command: echo HELLO</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">Then report in one line exactly what happened.</span></span></code></pre></figure>
<p><code>description</code> decides when the model reaches for it. The body is what it follows once loaded. The skill itself does nothing. The model reading it does the work.</p>
<h3>Agent</h3>
<p>An agent definition gives you a subagent, a clean context that takes a task, finishes it, and hands a summary back. The steps in between never reach the main thread.</p>
<p>The CLI reads <code>.claude/agents/&#x3C;name>.md</code>. The SDK takes the same fields through the <code>agents</code> option of <code>query()</code>.</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="markdown" data-theme="github-dark github-light"><code data-language="markdown" data-theme="github-dark github-light" style="display: grid;"><span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-dark-font-weight:bold;--shiki-light:#005CC5;--shiki-light-font-weight:bold">---</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">name: probe</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">description: Test agent for preloaded skills and tool limits.</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">skills: [</span><span style="--shiki-dark:#DBEDFF;--shiki-dark-text-decoration:underline;--shiki-light:#032F62;--shiki-light-text-decoration:underline">secretskill</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">]</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">tools: [Read, Bash]</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">model: haiku</span></span>
<span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-dark-font-weight:bold;--shiki-light:#005CC5;--shiki-light-font-weight:bold">---</span></span>
<span data-line=""> </span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">You are a test agent. Answer exactly what is asked.</span></span></code></pre></figure>
<p>Leave <code>tools</code> out and the subagent inherits everything from its parent agent. List them and it gets only those, and that limit holds. A subagent defined with <code>tools: ["Read"]</code>, told to run <code>echo HELLO</code>, replies that <code>Bash</code> is not in its tool set and there was nothing to call.</p>
<h3>Hook</h3>
<p>A hook is one rule in <code>settings.json</code>: which event, what the matcher matches, what runs.</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="json" data-theme="github-dark github-light"><code data-language="json" data-theme="github-dark github-light" style="display: grid;"><span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">{</span></span>
<span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">  "hooks"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">: {</span></span>
<span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">    "PreToolUse"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">: [{</span></span>
<span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">      "matcher"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">: </span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62">"Write|Edit"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">,</span></span>
<span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">      "hooks"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">: [{ </span><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">"type"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">: </span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62">"command"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">, </span><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">"command"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">: </span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62">"bash ~/hooks/prose-guard.sh"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E"> }]</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">    }]</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">  }</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">}</span></span></code></pre></figure>
<p>The <a href="https://code.claude.com/docs/en/hooks-reference">official reference</a> defines 33 events:</p>
<pre><code>PreToolUse         PostToolUse        PostToolUseFailure  PostToolBatch
Notification       UserPromptSubmit   UserPromptExpansion SessionStart
SessionEnd         Stop               StopFailure         SubagentStart
SubagentStop       PreCompact         PostCompact         PreModelSwitch
PostModelSwitch    PermissionRequest  PermissionDenied    Setup
TeammateIdle       TaskCreated        TaskCompleted       Elicitation
ElicitationResult  ConfigChange       WorktreeCreate      WorktreeRemove
InstructionsLoaded CwdChanged         FileChanged         DirectoryAdded
MessageDisplay
</code></pre>
<p>These five are the ones I reach for.</p>
<ul>
<li><code>PreToolUse</code> runs before a tool and can deny the call</li>
<li><code>PostToolUse</code> runs after a tool succeeds</li>
<li><code>UserPromptSubmit</code> runs after the prompt is submitted and before the model reads it</li>
<li><code>SessionStart</code> runs once at the start</li>
<li><code>Stop</code> runs when a turn ends</li>
</ul>
<p>The matcher is a regex against the tool name. Empty or <code>*</code> matches everything on that event. A broken regex will not stop the session; it prints <code>Invalid regex pattern in hook matcher</code>, counts as no match, and otherwise stays quiet, so a broken one is easy to miss.</p>
<p>Five kinds of action can run:</p>





























<table><thead><tr><th>type</th><th>what runs</th></tr></thead><tbody><tr><td><code>command</code></td><td>a shell command, hook input on stdin</td></tr><tr><td><code>prompt</code></td><td>a small model deciding whether a condition holds</td></tr><tr><td><code>agent</code></td><td>an agent deciding, <code>model</code> selectable, Haiku if you leave it out</td></tr><tr><td><code>mcp_tool</code></td><td>a tool on an MCP server you already configured</td></tr><tr><td><code>http</code></td><td>a POST of the hook input to a URL</td></tr></tbody></table>
<p>The last three only work on the tool events: <code>PreToolUse</code>, <code>PostToolUse</code>, <code>PermissionRequest</code>.</p>
<h2>Direction</h2>
<p>A tool is always the one being called. The callers are the model, a subagent, or the engine. <code>Agent</code> and <code>Skill</code> are no exception. The model calls them; they call nobody.</p>
<p>There is one case where running a tool starts something else, and it happens outside Claude Code. An MCP server you wrote yourself gets <code>tools/call</code>, and from there your code can do anything, including opening a fresh session. A <code>delegate</code> tool that shells out to <code>claude -p</code> returns <code>delegated-agent said: DELEGATED-OK</code>. Your node process is the caller, not any harness mechanism, so CLI and SDK make no difference here. Built-in tools have no such room. <code>Bash</code> finishes and that is the end of it.</p>
<p>"A tool calling a hook" points the wrong way too. Here is what actually runs.</p>
<p><code>settings.json</code> holds a <code>PreToolUse</code> entry whose matcher is <code>Bash</code>. When the model wants to run Bash, the engine checks that table first, runs the matching script, waits to see whether it allows the call, and only then does Bash execute.</p>
<p>Nothing in the Bash tool's own definition names that script. Delete the entry from <code>settings.json</code> and Bash behaves exactly the same. The hook is the thing being attached, and the place it attaches to is the moment before Bash runs.</p>
<h2>The sixteen combinations</h2>
<p>Every combination ran in its own directory. The strings are what <code>tool_result</code> actually came back with. The two Tool rows are written together, for the reason above.</p>

<p><strong>Subagent nesting</strong> is capped, not forbidden. The function that supplies the cap holds <code>var o=3</code>, so three levels by default. <code>CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH</code> or a feature flag overrides it. Go past it and you get <code>Subagent nesting limit reached (depth N)</code>.</p>
<p><strong>A hook wanting to run a skill</strong> has no field for it, so it goes the long way. The hook returns <code>additionalContext</code>, that text lands in the model's context, and the model calls the <code>Skill</code> tool itself.</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="json" data-theme="github-dark github-light"><code data-language="json" data-theme="github-dark github-light" style="display: grid;"><span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">{</span><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">"hookSpecificOutput"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">:{</span><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">"hookEventName"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">:</span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62">"UserPromptSubmit"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">,</span></span>
<span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5"> "additionalContext"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">:</span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62">"You must now invoke the skill named greet using the Skill tool before answering."</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">}}</span></span></code></pre></figure>
<p>Type <code>Say hello.</code> and the next line of the log is <code>TOOL_USE:Skill {"skill": "greet"}</code>, then <code>GREET-RAN</code>. This route needs the model to play along, so it gives you nothing like the guarantee of an <code>mcp_tool</code> hook. That one the engine runs directly, without the model in the path.</p>
<h2>The fields that wire a skill to the other three</h2>
<h3>To tools</h3>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="markdown" data-theme="github-dark github-light"><code data-language="markdown" data-theme="github-dark github-light" style="display: grid;"><span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-dark-font-weight:bold;--shiki-light:#005CC5;--shiki-light-font-weight:bold">---</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">name: restricttest</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">description: Test skill. Use when the user says restricttest.</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">allowed-tools: Read</span></span>
<span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-dark-font-weight:bold;--shiki-light:#005CC5;--shiki-light-font-weight:bold">---</span></span>
<span data-line=""> </span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">Call the Bash tool with command: echo HELLO</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">Then state in one line whether the Bash call succeeded or was refused.</span></span></code></pre></figure>
<p><code>allowed-tools: Read</code> looks like an allowlist, as though writing it leaves only Read available. It is not.</p>
<p>This skill lists only <code>Read</code>, its body asks for Bash, and both CLI and SDK run it anyway:</p>
<pre><code>assistant | TOOL_USE:Bash {"command":"echo HELLO"}
user      | TOOL_RESULT:"HELLO"
</code></pre>
<p>The engine turns the field into a context layer of kind <code>allowed_tools</code>, which sits in the permission system and marks the listed tools as pre-approved. If you want to limit what is reachable, a subagent's <code>tools</code> is the only field that does it.</p>
<p>The SDK option of the same name means the same thing, per the <a href="https://code.claude.com/docs/en/agent-sdk/typescript">TypeScript Agent SDK reference</a>:</p>
<blockquote>
<p>Tools to auto-approve without prompting. This does not restrict Claude to only these tools. […] Use <code>disallowedTools</code> to block tools.</p>
</blockquote>
<h3>To a subagent</h3>

<h2>Does the SDK behave differently</h2>
<p>No. Every combination above returns the same strings when the SDK drives it.</p>
<p>The packaging is why. On the <a href="https://registry.npmjs.org/@anthropic-ai/claude-agent-sdk">npm registry entry</a>, the latest <code>@anthropic-ai/claude-agent-sdk</code> is 0.3.252; unpack the tarball and there is no cli.js in it, only <code>sdk.mjs</code>, <code>bridge.mjs</code>, <code>extractFromBunfs.js</code>, plus the eight platform packages in <code>optionalDependencies</code>. The SDK drives the same native binary the CLI does, so frontmatter parsing, hook dispatch, and permission layering are one implementation. The versions move together: CLI 2.1.252, SDK 0.3.252.</p>
<p>Where the two differ is how configuration gets in. The CLI reads <code>.claude/agents/*.md</code> and layered <code>settings.json</code> files. The SDK takes <code>agents</code>, <code>mcpServers</code>, and hook callbacks as options, and does not touch filesystem settings unless <code>settingSources</code> says so; the boundaries are listed under <a href="https://code.claude.com/docs/en/agent-sdk/claude-code-features#what-settingsources-does-not-control">what settingSources does not control</a>.</p>
<h2>Version</h2>
<p>All of the above is 2.1.252 and 0.3.252. Some of these fields are new, <code>mcp_tool</code> hooks among them, and the nesting cap sits behind a feature flag, so another version can give another answer.</p>16:T37cb,
There are four things you can configure in Claude Code: skills, agents, tools, hooks. Each lives in its own file, and with the right field one can start another. That gives sixteen combinations, and every one of them was run.

Environment:

- CLI 2.1.252
- Agent SDK 0.3.252

## The four

### Tool

A tool is a function the model can call. A name and a parameter schema, nothing else.

Names come in two shapes.

Built-ins are short: `Read`, `Write`, `Edit`, `Bash`, `Grep`, `Glob`, `WebFetch`, `WebSearch`.

MCP servers give you `mcp__<server>__<tool>`, like `mcp__claude_ai_Jira__getJiraIssue`.

The difference only shows up when writing a hook matcher. To catch Bash, write `Bash`. To catch a whole MCP server, write `mcp__claude_ai_Jira__.*`, because without the trailing part the matcher hits nothing.

Here is my own local tool frequency, roughly. 87 session transcripts, 12,017 calls.

```
  6388  Bash
  3384  Edit
  1129  Read
   585  Write
   181  WebSearch
   165  WebFetch
    43  Skill
    36  ToolSearch
    31  Agent
    27  AskUserQuestion
    25  Artifact
    12  mcp__claude-in-chrome__tabs_context_mcp
```

Bash alone is half of it. `Grep` and `Glob` are missing because I habitually use bash; one command chains `find`, `grep`, and `head`, where the built-in tools would be three separate calls.

`Agent` and `Skill` are on the same list. Starting a subagent is the model calling a tool named `Agent`. Running a skill is the model calling one named `Skill`. Same shape as calling `Bash`, just with a bigger effect.

Which gives you one useful place to intervene. A `PreToolUse` hook with matcher `Agent` runs before every subagent launch, and it can deny the launch.

### Skill

A skill is a `SKILL.md`. Frontmatter on top, instructions for the model below.

```markdown
---
name: hooktest
description: Test skill. Use when the user says hooktest.
---

Call the Bash tool with command: echo HELLO
Then report in one line exactly what happened.
```

`description` decides when the model reaches for it. The body is what it follows once loaded. The skill itself does nothing. The model reading it does the work.

### Agent

An agent definition gives you a subagent, a clean context that takes a task, finishes it, and hands a summary back. The steps in between never reach the main thread.

The CLI reads `.claude/agents/<name>.md`. The SDK takes the same fields through the `agents` option of `query()`.

```markdown
---
name: probe
description: Test agent for preloaded skills and tool limits.
skills: [secretskill]
tools: [Read, Bash]
model: haiku
---

You are a test agent. Answer exactly what is asked.
```

Leave `tools` out and the subagent inherits everything from its parent agent. List them and it gets only those, and that limit holds. A subagent defined with `tools: ["Read"]`, told to run `echo HELLO`, replies that `Bash` is not in its tool set and there was nothing to call.

### Hook

A hook is one rule in `settings.json`: which event, what the matcher matches, what runs.

```json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Write|Edit",
      "hooks": [{ "type": "command", "command": "bash ~/hooks/prose-guard.sh" }]
    }]
  }
}
```

The [official reference](https://code.claude.com/docs/en/hooks-reference) defines 33 events:

```
PreToolUse         PostToolUse        PostToolUseFailure  PostToolBatch
Notification       UserPromptSubmit   UserPromptExpansion SessionStart
SessionEnd         Stop               StopFailure         SubagentStart
SubagentStop       PreCompact         PostCompact         PreModelSwitch
PostModelSwitch    PermissionRequest  PermissionDenied    Setup
TeammateIdle       TaskCreated        TaskCompleted       Elicitation
ElicitationResult  ConfigChange       WorktreeCreate      WorktreeRemove
InstructionsLoaded CwdChanged         FileChanged         DirectoryAdded
MessageDisplay
```

These five are the ones I reach for.

- `PreToolUse` runs before a tool and can deny the call
- `PostToolUse` runs after a tool succeeds
- `UserPromptSubmit` runs after the prompt is submitted and before the model reads it
- `SessionStart` runs once at the start
- `Stop` runs when a turn ends

The matcher is a regex against the tool name. Empty or `*` matches everything on that event. A broken regex will not stop the session; it prints `Invalid regex pattern in hook matcher`, counts as no match, and otherwise stays quiet, so a broken one is easy to miss.

Five kinds of action can run:

| type | what runs |
|---|---|
| `command` | a shell command, hook input on stdin |
| `prompt` | a small model deciding whether a condition holds |
| `agent` | an agent deciding, `model` selectable, Haiku if you leave it out |
| `mcp_tool` | a tool on an MCP server you already configured |
| `http` | a POST of the hook input to a URL |

The last three only work on the tool events: `PreToolUse`, `PostToolUse`, `PermissionRequest`.

## Direction

A tool is always the one being called. The callers are the model, a subagent, or the engine. `Agent` and `Skill` are no exception. The model calls them; they call nobody.

There is one case where running a tool starts something else, and it happens outside Claude Code. An MCP server you wrote yourself gets `tools/call`, and from there your code can do anything, including opening a fresh session. A `delegate` tool that shells out to `claude -p` returns `delegated-agent said: DELEGATED-OK`. Your node process is the caller, not any harness mechanism, so CLI and SDK make no difference here. Built-in tools have no such room. `Bash` finishes and that is the end of it.

"A tool calling a hook" points the wrong way too. Here is what actually runs.

`settings.json` holds a `PreToolUse` entry whose matcher is `Bash`. When the model wants to run Bash, the engine checks that table first, runs the matching script, waits to see whether it allows the call, and only then does Bash execute.

Nothing in the Bash tool's own definition names that script. Delete the entry from `settings.json` and Bash behaves exactly the same. The hook is the thing being attached, and the place it attaches to is the moment before Bash runs.

## The sixteen combinations

Every combination ran in its own directory. The strings are what `tool_result` actually came back with. The two Tool rows are written together, for the reason above.

| Caller and target | CLI 2.1.252 | SDK 0.3.252 |
|---|---|---|
| SubAgent calls SubAgent | works, one level down returns `NESTED-OK` | same |
| SubAgent calls Hook | frontmatter `hooks:` has no effect | no effect |
| SubAgent calls Tool | works, inherits everything by default | works, `tools:["Read"]` really does limit it |
| SubAgent calls Skill | works, returns `MAGENTA-PELICAN-42` | same token |
| Hook calls SubAgent | works, `Agent hook condition was not met: AGENT-HOOK-BLOCKED` | same string |
| Hook calls Hook | no such mechanism | not tested |
| Hook calls Tool | works, server records `note="echo MAIN"` | same |
| Hook calls Skill | works the long way round, ends at `GREET-RAN` | same |
| Skill calls SubAgent | works, `Skill "forktest" completed (forked execution).` | same string |
| Skill calls Hook | works, `BLOCKED-BY-SKILL-HOOK` | same string |
| Skill calls Tool | works, but `allowed-tools` is not a restriction | same |
| Skill calls Skill | works, returns `INNER-RAN` | same |
| Tool calls SubAgent / Skill / Tool | no such path in the harness; your MCP server's own code can, returning `delegated-agent said: DELEGATED-OK` | same, has nothing to do with the runtime |
| Tool calls Hook | backwards: the engine consults the hook table around the call | same |

**Subagent nesting** is capped, not forbidden. The function that supplies the cap holds `var o=3`, so three levels by default. `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` or a feature flag overrides it. Go past it and you get `Subagent nesting limit reached (depth N)`.

**A hook wanting to run a skill** has no field for it, so it goes the long way. The hook returns `additionalContext`, that text lands in the model's context, and the model calls the `Skill` tool itself.

```json
{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit",
 "additionalContext":"You must now invoke the skill named greet using the Skill tool before answering."}}
```

Type `Say hello.` and the next line of the log is `TOOL_USE:Skill {"skill": "greet"}`, then `GREET-RAN`. This route needs the model to play along, so it gives you nothing like the guarantee of an `mcp_tool` hook. That one the engine runs directly, without the model in the path.

## The fields that wire a skill to the other three

### To tools

```markdown
---
name: restricttest
description: Test skill. Use when the user says restricttest.
allowed-tools: Read
---

Call the Bash tool with command: echo HELLO
Then state in one line whether the Bash call succeeded or was refused.
```

`allowed-tools: Read` looks like an allowlist, as though writing it leaves only Read available. It is not.

This skill lists only `Read`, its body asks for Bash, and both CLI and SDK run it anyway:

```
assistant | TOOL_USE:Bash {"command":"echo HELLO"}
user      | TOOL_RESULT:"HELLO"
```

The engine turns the field into a context layer of kind `allowed_tools`, which sits in the permission system and marks the listed tools as pre-approved. If you want to limit what is reachable, a subagent's `tools` is the only field that does it.

The SDK option of the same name means the same thing, per the [TypeScript Agent SDK reference](https://code.claude.com/docs/en/agent-sdk/typescript):

> Tools to auto-approve without prompting. This does not restrict Claude to only these tools. […] Use `disallowedTools` to block tools.

### To a subagent

```markdown
---
name: forktest
description: Test skill. Use when the user says forktest.
context: fork
agent: Explore
---

Reply with exactly one word: FORKED
```

The skill body becomes the task prompt of a subagent of that type, and only the result comes back:

```
Skill "forktest" completed (forked execution).

Result:
FORKED
```

`(forked execution)` is how you tell them apart. An ordinary inline run returns `Launching skill: <name>`.

### To a hook

```markdown
---
name: hooktest
description: Test skill. Use when the user says hooktest.
hooks:
  PreToolUse:
    - matcher: Bash
      hooks:
        - type: command
          command: bash .claude/skills/hooktest/deny.sh
---

Call the Bash tool with command: echo HELLO
Then report in one line exactly what happened.
```

One line of JSON in `deny.sh` is enough:

```bash
#!/bin/bash
echo '{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"BLOCKED-BY-SKILL-HOOK"}}'
```

Invoke that skill and its `echo HELLO` comes back as `BLOCKED-BY-SKILL-HOOK`, with the command never running.

The rule belongs to that skill alone. In the same session, `echo HELLO` outside the skill still prints `HELLO`.

Agent definitions take a `hooks:` field too. It loads without complaint and does nothing.

Copying that same deny rule into `.claude/agents/probe.md` and asking probe to run `echo SUB` returns `SUB`, the command running normally. Making probe the main agent with `--agent probe` gives the same result. Adding a line to deny.sh that writes a marker file leaves the marker empty afterwards, so the script never ran at all. CLI and SDK both behave this way.

## How this was checked

One directory per case, so settings do not leak between them.

CLI:

```bash
claude -p "Invoke the hooktest skill now." \
       --output-format stream-json --verbose
```

One JSON event per line. Pull out the `tool_use` and `tool_result` blocks and you see what the model called and what it got back.

SDK:

```javascript
import { query } from "@anthropic-ai/claude-agent-sdk";
const q = query({
  prompt: "Invoke the hooktest skill now.",
  options: { cwd: process.cwd(), settingSources: ["project"],
             skills: "all", permissionMode: "bypassPermissions" }
});
for await (const m of q) console.log(m.type, JSON.stringify(m.message?.content));
```

`settingSources: ["project"]` is not optional. It is what makes the SDK read `.claude/settings.json` from the working directory, and without it the project's hooks are never registered at all.

Whether a hook ran is invisible in the message stream, since hooks never appear there. For those cases, have the hook write a marker file as well:

```bash
#!/bin/bash
date +%s >> marker.txt
```

`cat` it afterwards. Empty means it never ran, which is how the agent-frontmatter case was settled.

The `mcp_tool` case needs a server. Fifty lines of stdio server covers it: implement `initialize`, `tools/list`, and `tools/call`, and have `tools/call` append its arguments to a file. The hook entry:

```json
{"type":"mcp_tool","server":"marker","tool":"record",
 "input":{"note":"${tool_input.command}"}}
```

Run `echo MAIN` and the file holds `CALLED note="echo MAIN"`, which also shows that `${tool_input.command}` is replaced with the real command.

## Does the SDK behave differently

No. Every combination above returns the same strings when the SDK drives it.

The packaging is why. On the [npm registry entry](https://registry.npmjs.org/@anthropic-ai/claude-agent-sdk), the latest `@anthropic-ai/claude-agent-sdk` is 0.3.252; unpack the tarball and there is no cli.js in it, only `sdk.mjs`, `bridge.mjs`, `extractFromBunfs.js`, plus the eight platform packages in `optionalDependencies`. The SDK drives the same native binary the CLI does, so frontmatter parsing, hook dispatch, and permission layering are one implementation. The versions move together: CLI 2.1.252, SDK 0.3.252.

Where the two differ is how configuration gets in. The CLI reads `.claude/agents/*.md` and layered `settings.json` files. The SDK takes `agents`, `mcpServers`, and hook callbacks as options, and does not touch filesystem settings unless `settingSources` says so; the boundaries are listed under [what settingSources does not control](https://code.claude.com/docs/en/agent-sdk/claude-code-features#what-settingsources-does-not-control).

<h2>四個元件</h2>
<h3>Tool</h3>
<p>Tool 就是模型能呼叫的函式，一個名字加一份參數 schema，沒別的。</p>
<p>名字分兩種。</p>
<p>內建的短，<code>Read</code>、<code>Write</code>、<code>Edit</code>、<code>Bash</code>、<code>Grep</code>、<code>Glob</code>、<code>WebFetch</code>、<code>WebSearch</code> 都是。</p>
<p>MCP server 給的長，長成 <code>mcp__&#x3C;server>__&#x3C;tool></code>，例如 <code>mcp__claude_ai_Jira__getJiraIssue</code>。</p>
<p>這個差別只有在寫 hook matcher 的時候會有感。要管 Bash 寫 <code>Bash</code> 就好，要涵蓋一整台 MCP server 得寫成 <code>mcp__claude_ai_Jira__.*</code>，少了後面那段等於沒設。</p>
<p>我拿我的本機工具頻率來看大致上是這樣，87 份 session 逐字檔、12017 次呼叫。</p>
<pre><code>  6388  Bash
  3384  Edit
  1129  Read
   585  Write
   181  WebSearch
   165  WebFetch
    43  Skill
    36  ToolSearch
    31  Agent
    27  AskUserQuestion
    25  Artifact
    12  mcp__claude-in-chrome__tabs_context_mcp
</code></pre>
<p>Bash 一支就佔一半。<code>Grep</code> 跟 <code>Glob</code> 沒在上面，是因為我習慣用 bash，一條指令就能把 <code>find</code>、<code>grep</code>、<code>head</code> 串起來，換成內建 tool 要分三次呼叫。</p>
<p><code>Agent</code> 跟 <code>Skill</code> 也在名單上。開一個 subagent 就是模型呼叫 <code>Agent</code> 這個 tool，跑一份 skill 就是呼叫 <code>Skill</code>。跟呼叫 <code>Bash</code> 同一回事，只是效果大一點。</p>
<p>好處是 matcher 寫 <code>Agent</code> 的 <code>PreToolUse</code> hook，每次要開 subagent 之前都會先跑，想否決也可以。</p>
<h3>Skill</h3>
<p>Skill 就是一份 <code>SKILL.md</code>。上面 frontmatter，下面寫給模型看的步驟。</p>

<h3>Agent</h3>
<p>Agent 定義開出來的 subagent 是一段乾淨的 context，接任務、自己做完、回結論給主線，中間過程不會進主線。</p>
<p>CLI 讀 <code>.claude/agents/&#x3C;name>.md</code>，SDK 走 <code>query()</code> 的 <code>agents</code> 選項，欄位一樣。</p>

<p><code>tools</code> 不寫就繼承 parent agent 的全部。寫了就只剩清單上那些，而且真的限制得住。定義成 <code>tools: ["Read"]</code> 的 subagent 叫它跑 <code>echo HELLO</code>，它回說 <code>Bash</code> 不在它的工具集裡，連選都選不到。</p>

<span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">      "hooks"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">: [{ </span><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">"type"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">: </span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62">"command"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">, </span><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">"command"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">: </span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62">"bash ~/hooks/prose-guard.sh"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E"> }]</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">    }]</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">  }</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">}</span></span></code></pre></figure>
<p><a href="https://code.claude.com/docs/en/hooks-reference">官方文件</a>定義了 33 種事件。</p>
<pre><code>PreToolUse         PostToolUse        PostToolUseFailure  PostToolBatch
Notification       UserPromptSubmit   UserPromptExpansion SessionStart
SessionEnd         Stop               StopFailure         SubagentStart
SubagentStop       PreCompact         PostCompact         PreModelSwitch
PostModelSwitch    PermissionRequest  PermissionDenied    Setup
TeammateIdle       TaskCreated        TaskCompleted       Elicitation
ElicitationResult  ConfigChange       WorktreeCreate      WorktreeRemove
InstructionsLoaded CwdChanged         FileChanged         DirectoryAdded
MessageDisplay
</code></pre>
<p>我常用到的是這五個。</p>
<ul>
<li><code>PreToolUse</code> 在 tool 執行之前跑，可以否決那次呼叫</li>
<li><code>PostToolUse</code> 在 tool 成功之後跑</li>
<li><code>UserPromptSubmit</code> 在訊息送出之後、模型讀到之前跑</li>
<li><code>SessionStart</code> 開場跑一次</li>
<li><code>Stop</code> 一輪結束跑</li>
</ul>
<p>Matcher 是正則，比對 tool 名字。留空或寫 <code>*</code> 就是全部命中。正則寫壞不會讓 session 停，只會 print 出一句 <code>Invalid regex pattern in hook matcher</code> 然後當作沒命中，所以寫壞了不太容易發現。</p>
<p>命中之後跑什麼分五種。</p>





























<table><thead><tr><th>type</th><th>跑什麼</th></tr></thead><tbody><tr><td><code>command</code></td><td>一段 shell 指令，hook 的輸入從 stdin 進去</td></tr><tr><td><code>prompt</code></td><td>一個小模型判斷條件成不成立</td></tr><tr><td><code>agent</code></td><td>一個 agent 做判斷，<code>model</code> 可以指定，不寫是 Haiku</td></tr><tr><td><code>mcp_tool</code></td><td>呼叫某台已經設定好的 MCP server 上的 tool</td></tr><tr><td><code>http</code></td><td>把 hook 輸入 POST 到一個 URL</td></tr></tbody></table>
<p>後三種只在 tool 相關的事件上可用，也就是 <code>PreToolUse</code>、<code>PostToolUse</code>、<code>PermissionRequest</code>。</p>
<h2>方向</h2>
<p>Tool 永遠是被呼叫的那一端，發動的是模型、subagent、或 engine。<code>Agent</code> 跟 <code>Skill</code> 這兩個也一樣，模型叫它們，它們不叫別人。</p>
<p>唯一 tool 跑起來會帶起另一段執行的情況，發生在 Claude Code 外面。自己寫的 MCP server 收到 <code>tools/call</code> 之後，那段程式碼想做什麼都行，開一個新 session 也行。實測一支 <code>delegate</code> tool 在實作裡跑 <code>claude -p</code>，回傳 <code>delegated-agent said: DELEGATED-OK</code>。發動的是那支 node，不是 harness 的機制，所以 CLI 還 SDK 沒差。內建 tool 沒這種空間，<code>Bash</code> 跑完就結束。</p>
<p>「tool 帶 hook」這個說法方向也反了。實際跑起來是這樣。</p>
<p><code>settings.json</code> 裡有一條 <code>PreToolUse</code>，matcher 寫 <code>Bash</code>。模型要跑 Bash 的時候，engine 先去翻這張表，翻到就執行那支 script，看它放不放行，才輪到 Bash 真的執行。</p>
<p>Bash 這個 tool 的定義裡沒有那支 script 的名字。把那條規則從 <code>settings.json</code> 刪掉，Bash 一模一樣照跑。所以掛上去的是 hook，被掛的位置是「Bash 執行前」這個時機。</p>
<h2>十六種組合</h2>
<p>下面每種組合都在自己的目錄跑過，字串是 <code>tool_result</code> 真的回傳的內容。Tool 那兩列合併寫，理由上一節講過了。</p>
















































































<table><thead><tr><th>誰呼叫誰</th><th>CLI 2.1.252</th><th>SDK 0.3.252</th></tr></thead><tbody><tr><td>SubAgent 呼叫 SubAgent</td><td>通，嵌一層回 <code>NESTED-OK</code></td><td>通，一樣</td></tr><tr><td>SubAgent 呼叫 Hook</td><td>frontmatter 的 <code>hooks:</code> 沒有效果</td><td>沒有效果</td></tr><tr><td>SubAgent 呼叫 Tool</td><td>通，預設繼承全部</td><td>通，<code>tools:["Read"]</code> 真的限制住</td></tr><tr><td>SubAgent 呼叫 Skill</td><td>通，回 <code>MAGENTA-PELICAN-42</code></td><td>通，同一個 token</td></tr><tr><td>Hook 呼叫 SubAgent</td><td>通，<code>Agent hook condition was not met: AGENT-HOOK-BLOCKED</code></td><td>通，同一句</td></tr><tr><td>Hook 呼叫 Hook</td><td>沒有這種機制</td><td>未測</td></tr><tr><td>Hook 呼叫 Tool</td><td>通，server 記到 <code>note="echo MAIN"</code></td><td>通，一樣</td></tr><tr><td>Hook 呼叫 Skill</td><td>繞一圈才通，最後回 <code>GREET-RAN</code></td><td>一樣</td></tr><tr><td>Skill 呼叫 SubAgent</td><td>通，<code>Skill "forktest" completed (forked execution).</code></td><td>通，同一句</td></tr><tr><td>Skill 呼叫 Hook</td><td>通，<code>BLOCKED-BY-SKILL-HOOK</code></td><td>通，同一句</td></tr><tr><td>Skill 呼叫 Tool</td><td>通，但 <code>allowed-tools</code> 不是限制</td><td>一樣</td></tr><tr><td>Skill 呼叫 Skill</td><td>通，回 <code>INNER-RAN</code></td><td>通，一樣</td></tr><tr><td>Tool 呼叫 SubAgent / Skill / Tool</td><td>harness 沒有這條路；MCP server 的實作碼可以，實測 <code>delegated-agent said: DELEGATED-OK</code></td><td>一樣，跟 runtime 無關</td></tr><tr><td>Tool 呼叫 Hook</td><td>方向相反，是 engine 在 tool 前後查 hook 表</td><td>一樣</td></tr></tbody></table>
<p><strong>Subagent 的巢狀</strong>不是不能，是有上限。給上限的那個函式裡寫著 <code>var o=3</code>，預設三層。<code>CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH</code> 或一個 feature flag 可以覆寫。超過會看到 <code>Subagent nesting limit reached (depth N)</code>。</p>
<p><strong>Hook 想叫 skill</strong> 沒有欄位可以寫，只能繞。Hook 回一段 <code>additionalContext</code> 塞進模型的 context，模型讀到之後自己去叫 <code>Skill</code> tool。</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="json" data-theme="github-dark github-light"><code data-language="json" data-theme="github-dark github-light" style="display: grid;"><span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">{</span><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">"hookSpecificOutput"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">:{</span><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">"hookEventName"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">:</span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62">"UserPromptSubmit"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">,</span></span>
<span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5"> "additionalContext"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">:</span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62">"You must now invoke the skill named greet using the Skill tool before answering."</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">}}</span></span></code></pre></figure>
<p>輸入 <code>Say hello.</code>，log 下一步就是 <code>TOOL_USE:Skill {"skill": "greet"}</code>，然後 <code>GREET-RAN</code>。這條路要模型配合，所以沒有 <code>mcp_tool</code> 那種保證。<code>mcp_tool</code> 是 engine 直接跑，不經過模型。</p>
<h2>Skill 串接另外三種的欄位</h2>
<h3>串接 tool</h3>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="markdown" data-theme="github-dark github-light"><code data-language="markdown" data-theme="github-dark github-light" style="display: grid;"><span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-dark-font-weight:bold;--shiki-light:#005CC5;--shiki-light-font-weight:bold">---</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">name: restricttest</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">description: Test skill. Use when the user says restricttest.</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">allowed-tools: Read</span></span>
<span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-dark-font-weight:bold;--shiki-light:#005CC5;--shiki-light-font-weight:bold">---</span></span>
<span data-line=""> </span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">Call the Bash tool with command: echo HELLO</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">Then state in one line whether the Bash call succeeded or was refused.</span></span></code></pre></figure>
<p><code>allowed-tools: Read</code> 看起來像白名單，寫了就只准用 Read。實際上不是。</p>
<p>這份 skill 的清單只有 <code>Read</code>，內文卻要求執行 Bash，CLI 跟 SDK 兩邊都照跑。</p>
<pre><code>assistant | TOOL_USE:Bash {"command":"echo HELLO"}
user      | TOOL_RESULT:"HELLO"
</code></pre>
<p>engine 把這個欄位轉成一層 kind 是 <code>allowed_tools</code> 的 context layer，位置在權限系統，效果是清單上那幾個免問就過。要真的限制可用範圍，只能靠 subagent 的 <code>tools</code>。</p>
<p>SDK 同名的選項語意一致，<a href="https://code.claude.com/docs/en/agent-sdk/typescript">Agent SDK 的 TypeScript reference</a> 這樣寫。</p>
<blockquote>
<p>Tools to auto-approve without prompting. This does not restrict Claude to only these tools. […] Use <code>disallowedTools</code> to block tools.</p>
</blockquote>
<h3>串接 subagent</h3>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="markdown" data-theme="github-dark github-light"><code data-language="markdown" data-theme="github-dark github-light" style="display: grid;"><span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-dark-font-weight:bold;--shiki-light:#005CC5;--shiki-light-font-weight:bold">---</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">name: forktest</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">description: Test skill. Use when the user says forktest.</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">context: fork</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">agent: Explore</span></span>
<span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-dark-font-weight:bold;--shiki-light:#005CC5;--shiki-light-font-weight:bold">---</span></span>
<span data-line=""> </span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">Reply with exactly one word: FORKED</span></span></code></pre></figure>
<p>Skill 內文直接變成那個 subagent 的任務描述，只有結果回主線。</p>
<pre><code>Skill "forktest" completed (forked execution).

Result:
FORKED
</code></pre>
<p><code>(forked execution)</code> 就是分辨的方法，一般 inline 跑完回的是 <code>Launching skill: &#x3C;name></code>。</p>
<h3>串接 hook</h3>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="markdown" data-theme="github-dark github-light"><code data-language="markdown" data-theme="github-dark github-light" style="display: grid;"><span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-dark-font-weight:bold;--shiki-light:#005CC5;--shiki-light-font-weight:bold">---</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">name: hooktest</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">description: Test skill. Use when the user says hooktest.</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">hooks:</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">  PreToolUse:</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">    - matcher: Bash</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">      hooks:</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">        - type: command</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">          command: bash .claude/skills/hooktest/deny.sh</span></span>
<span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-dark-font-weight:bold;--shiki-light:#005CC5;--shiki-light-font-weight:bold">---</span></span>
<span data-line=""> </span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">Call the Bash tool with command: echo HELLO</span></span>
<span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">Then report in one line exactly what happened.</span></span></code></pre></figure>
<p><code>deny.sh</code> 印一行 JSON 就夠。</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-dark github-light"><code data-language="bash" data-theme="github-dark github-light" style="display: grid;"><span data-line=""><span style="--shiki-dark:#6A737D;--shiki-light:#6A737D">#!/bin/bash</span></span>
<span data-line=""><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">echo</span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62"> '{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"BLOCKED-BY-SKILL-HOOK"}}'</span></span></code></pre></figure>
<p>呼叫這份 skill 之後，它內部的 <code>echo HELLO</code> 回傳 <code>BLOCKED-BY-SKILL-HOOK</code>，指令沒跑到。</p>
<p>這條規則只在那份 skill 身上。同一個 session 裡，skill 外面跑 <code>echo HELLO</code> 照樣輸出 <code>HELLO</code>。</p>
<p>Agent 定義也吃 <code>hooks:</code> 這個欄位，寫進去不會報錯，但沒有作用。</p>
<p>我把上面那條 deny 規則原封不動搬到 <code>.claude/agents/probe.md</code>，叫 probe 跑 <code>echo SUB</code>，它回傳 <code>SUB</code>，指令正常執行。改用 <code>--agent probe</code> 讓 probe 當主線，結果一樣。deny.sh 裡我另外加了一行寫 marker 檔案，跑完 marker 是空的，代表那支 script 從頭到尾沒被執行過。CLI 跟 SDK 兩邊都這樣。</p>
<h2>怎麼測的</h2>
<p>每種組合開一個獨立目錄跑，免得設定互相汙染。</p>
<p>CLI:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-dark github-light"><code data-language="bash" data-theme="github-dark github-light" style="display: grid;"><span data-line=""><span style="--shiki-dark:#B392F0;--shiki-light:#6F42C1">claude</span><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5"> -p</span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62"> "Invoke the hooktest skill now."</span><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5"> \</span></span>

<p>輸出一行一個 JSON 事件，挑 <code>tool_use</code> 跟 <code>tool_result</code> 兩種 block 出來看就知道模型叫了什麼又拿回什麼。</p>

<p><code>settingSources: ["project"]</code> 不能少，SDK 要靠它才會讀工作目錄的 <code>.claude/settings.json</code>，不寫的話專案裡的 hook 根本沒被註冊。</p>
<p>Hook 有沒有真的執行，光看訊息串流看不出來，因為 hook 不會出現在裡面。這種就讓 hook 順便寫一個 marker 檔。</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-dark github-light"><code data-language="bash" data-theme="github-dark github-light" style="display: grid;"><span data-line=""><span style="--shiki-dark:#6A737D;--shiki-light:#6A737D">#!/bin/bash</span></span>
<span data-line=""><span style="--shiki-dark:#B392F0;--shiki-light:#6F42C1">date</span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62"> +%s</span><span style="--shiki-dark:#F97583;--shiki-light:#D73A49"> >></span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62"> marker.txt</span></span></code></pre></figure>
<p>跑完 <code>cat</code> 一下，空的就是沒執行過。Agent frontmatter 的 <code>hooks:</code> 就是這樣判定沒生效的。</p>
<p>測 <code>mcp_tool</code> 要有一台 server。手寫一支五十行的 stdio server 就夠，實作 <code>initialize</code>、<code>tools/list</code>、<code>tools/call</code> 三個方法，<code>tools/call</code> 把參數附加到檔案。Hook 這樣設。</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="json" data-theme="github-dark github-light"><code data-language="json" data-theme="github-dark github-light" style="display: grid;"><span data-line=""><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">{</span><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">"type"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">:</span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62">"mcp_tool"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">,</span><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">"server"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">:</span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62">"marker"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">,</span><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5">"tool"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">:</span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62">"record"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E">,</span></span>

<p>跑一次 <code>echo MAIN</code>，檔案裡出現 <code>CALLED note="echo MAIN"</code>，順便證明 <code>${tool_input.command}</code> 會被代換成真正的指令。</p>
<h2>用 SDK 跑會不一樣嗎</h2>
<p>不會。上面每一種組合，換成 SDK 驅動，回傳的字串一模一樣。</p>
<p>原因在打包方式。<a href="https://registry.npmjs.org/@anthropic-ai/claude-agent-sdk">npm registry 上的 <code>@anthropic-ai/claude-agent-sdk</code></a> 最新版是 0.3.252，解開 tarball 裡面沒有 cli.js，只有 <code>sdk.mjs</code>、<code>bridge.mjs</code> 跟 <code>extractFromBunfs.js</code>，加上 <code>optionalDependencies</code> 那八個平台專屬套件。SDK 驅動的就是 CLI 那顆原生 binary，frontmatter 的解析、hook 的派送、權限層的疊加全是同一份 code。版本號也同步走，CLI 2.1.252 對 SDK 0.3.252。</p>
<p>兩邊真的有差的地方在設定怎麼進去。CLI 讀 <code>.claude/agents/*.md</code> 跟分層的 <code>settings.json</code>；SDK 是把 <code>agents</code>、<code>mcpServers</code>、hook callback 當參數傳，而且不指定 <code>settingSources</code> 的話它不讀檔案系統上的設定，細節在 <a href="https://code.claude.com/docs/en/agent-sdk/claude-code-features#what-settingsources-does-not-control">what settingSources does not control</a>。</p>
