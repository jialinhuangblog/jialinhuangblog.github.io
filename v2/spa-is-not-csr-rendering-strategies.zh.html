CSR SPA 曾經嚴重混淆

frontendspacsrssrrendering

我是 2017 年開始寫程式的，那時 Angular、React、Vue 三足鼎立，也流行 SPA 框架。又或者說，其實我只知道這種框架，不知道什麼 ASP.NET 的 SSR。後來接觸到 Next.js，我才知道 SSR，也才因為 SSR 知道相對的 CSR。在這之前，我一直以為 SPA 就等於 CSR，SSR 出現是要解決 SPA 的問題，是這樣的印象。

可是 SPA 跟 CSR 指的是兩件不同的事。

  • SPA（Single-Page Application）是指換頁時由瀏覽器裡的 JS 更新畫面，不向 server 要一整頁新的 HTML。
  • CSR（Client-Side Rendering）是指第一頁的 HTML 由瀏覽器裡的 JS 組出來，server 只送一個幾乎是空的 HTML 跟 JS 檔。

Angular CLI、Create React App、Vue CLI 預設產生的 app，兩件事都做，所以這兩個詞很容易被當成同一件事。

SPA 跟 CSR 是怎麼分開的

讓 SPA 的第一頁先在 server 產生，也就是 SSR（Server-Side Rendering），其實很早就有人做。2012 年的 Rendr 讓 Backbone app 在 server 跟瀏覽器都能 render（rendrjs/rendr），2013 年 React 0.4 就有 renderComponentToString，可以在 server 上產生 HTML 送給瀏覽器（React CHANGELOG）。只是開發者得自己寫一個 Node server，收到請求後呼叫這類函式產生 HTML，再讓瀏覽器端接手換頁。Next.js 在 2016 年把 SSR 變成預設，pages/ 裡的每個 component 都自動在 server render，換頁還是交給瀏覽器的 JS（Next.js 發表文）。一個用 Next.js Pages Router 做的網站，第一頁是 server render 的，不是 CSR，可是換頁的方式跟 SPA 一模一樣，所以它還是 SPA。

年代發生什麼SPA 跟 CSR 的關係
2010–2014SPA 出現：Backbone、Angular 1、Ember預設都用 CSR，實務上 SPA 就等於 CSR
2014–2018React、Vue 成為主流大多數還是 SPA 加 CSR，server render 要自己接，兩個詞在日常用法裡變成同義詞
2016–2020Next.js、Nuxt、Gatsby 把 SSR、SSG（Static Site Generation）變成預設換頁還在 client 端，所以還是 SPA，但第一頁不再是 CSR
2023 起Next.js 13.4 的 App Router 進入 stable，它用的是 React Server Components；React 19（2024 年 12 月）才把 React Server Components 列為 stable同一頁裡，有些 component 只在 server 上執行，有些會送到瀏覽器執行，CSR、SSR、SSG 三種分法不夠用了

每個名詞都帶著它出現那個年代的預設。「SPA」預設是 CSR，因為它就是在那個年代出現的。「SSR」隱含「會做 hydration」，因為這個詞的用法是 React、Vue、Svelte 這一派建立起來的。

SPA 換頁時做了什麼

傳統的 MPA（Multi-Page Application）每換一頁就向 server 要一整頁。點一個連結之後，兩種做法依序會發生這些事：

傳統 MPASPA
1瀏覽器向 server 送 GETrouter（一段 JS）攔下這次點擊
2server 回傳一整頁 HTML需要的話，用 fetch 向 server 要資料
3瀏覽器卸載目前的頁面原地更新 DOM
4render 新頁面，JS 從頭執行用 history.pushState 改網址，頁面沒有卸載過

使用者感覺很快，沒有白畫面閃一下，像在用 app。server 收到的 request 多半是要特定的資料，跟 MPA 每次要一整頁不同。

這些都沒有講到第一頁是怎麼 render 出來的，那是另一個問題。〈五種網頁渲染方式，伺服器跟瀏覽器各做了什麼〉那篇用動畫比較了五種做法，畫出每一種做法裡，第一頁的 HTML 由 server 還是瀏覽器組出來。

換頁方式跟第一頁的 render 各自決定

要決定的事選項
換頁體驗SPA（頁面內更新）或 MPA（整頁重新載入）
第一次 render 的策略CSR / SSR / SSG / RSC（React Server Components）/ Islands

兩件事各選一種。常見的組合：

  • SPA + CSR：Create React App（React 在 2025 年 2 月已宣布棄用，React 官方公告）、Vue CLI、Angular CLI 預設產生的 app，現在用 Vite 開的 React、Vue 專案也是
  • SPA + SSR + hydration：Next.js Pages Router（頁面有 getServerSideProps 或 getInitialProps，或自訂的 _app 有 getInitialProps 的時候；都沒有的話，Next.js 在 build 時就先產生靜態 HTML）、Remix、SvelteKit、Nuxt
  • SPA + SSG + hydration：Gatsby、Next.js 的 static export（output: 'export'，這個網站就是）
  • SPA + RSC + 只對 client component 做 hydration：Next.js App Router（13.4 起 stable，2023 年）
  • MPA + 純 server-render：Django、Laravel 的 Blade、傳統 PHP。Rails 7 起新專案預設裝了 Turbo Drive，換頁就變成下面 Turbo Drive 那段講的方式，不整頁重新載入
  • MPA + Islands：Astro（預設模式）。Islands 是指頁面大部分是 server 產生的純 HTML，只有少數需要互動的 component 會在瀏覽器做 hydration

SSR、SSG 送來的 HTML 只有畫面。HTML 本身可以帶 onclick="..." 這種寫成字串的 handler，可是 React、Vue 這類框架的 event handler 是 component 裡的 function，會用到 component 的 state 跟 props，沒辦法轉成這種字串送下來。所以瀏覽器要再下載 component 的 JS，重新執行 component，把 handler 接到現成的 DOM 上，這一步叫 hydration。框架的 router 也跟著這批 JS 進到瀏覽器，之後的換頁才由瀏覽器處理。

不做 hydration 也能做到 SPA 式的換頁。Turbo Drive 會攔下連結的點擊，fetch 下一頁 server render 好的 HTML 換掉 <body>，不整頁重新載入（Turbo handbook）。Astro 的 <ClientRouter /> 也是攔下點擊，再 fetch 下一頁的 HTML 換上去（Astro docs）。
