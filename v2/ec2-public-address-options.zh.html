EC2 每次重開 IP 都會換，怎麼讓它有固定的位址

2024/10/07
awsec2networkingroute53

在 AWS 開一台 EC2，它會自動拿到一個 public IP。把 DNS record 指過去，就可以開始用了。可是如果為了省錢晚上把它 stop，隔天早上再 start，IP 就換了，所有指向舊 IP 的連結都會失效。

自動配的 IP 是浮動的，要讓別人一直連得上，就需要一個不會變的位址。常見的做法有三種。

1. 自動配發的 public IP

不用任何設定，但 AWS 每次 stop 都會收回這個 IP，start 時再配一個新的。用完就丟的機器用它沒問題，需要讓人固定找到的服務就不適合。

2. Elastic IP

Elastic IP 是綁在 AWS 帳號上的固定位址。把它 attach 到 instance，再設一筆 A record 指過去就好，重開機也不會變。

以前它只要 attach 在 instance 上就不收錢，現在要收了。從 2024 年 2 月 1 日起，每個 public IPv4 位址每小時收 0.005 美元（一個月大約 3.6 美元），不管有沒有在用都算，而 VPC 價目頁現在列的也還是這個價格。沒 attach 在任何東西上的 Elastic IP 也一樣計費，用不到的就 release 掉。

如果帳號是 2025 年 7 月 15 日以前開的，free tier 在前 12 個月每月送 750 小時的 public IPv4，剛好夠一個位址整個月開著。之後開的帳號，free tier 改成開戶時送 100 美元的 credit，期限是六個月，credit 先用完就提早結束。EC2 的 free tier 文件講到這種帳號時，沒有再列那 750 小時，也沒寫這筆 credit 能不能拿來付 public IPv4 的錢。

3. DDNS

DDNS（Dynamic DNS）的做法是保留會變的 IP，在它前面放一個名字。instance 上跑一支小 client，一直重複下面兩個步驟。

  1. 查詢自己現在的 public IP。作業系統的網路介面上只有 private IP，因為 internet gateway 會替它做 NAT，所以 client 要去問外部的服務，或是問 instance metadata endpoint。
  2. 如果 IP 變了，就通知 DNS 服務商，把名字改指到新的 IP。

這支 client 不用自己寫。DDNS 服務商通常會提供自己的 client，例如 No-IP 的 DUC（Dynamic Update Client）。如果不想綁定某一家，也可以用開源的 ddclient，它支援大部分服務商，在 Ubuntu 上跑 apt install ddclient 就能安裝。以 No-IP 為例，ddclient 的範例設定檔大概長這樣：

# /etc/ddclient.conf
daemon=300                                 # 每 300 秒檢查一次
use=web, web=checkip.dyndns.org/, web-skip='IP Address'   # 去外部服務查自己的 public IP
protocol=noip, ssl=yes, server=dynupdate.no-ip.com
login=your-noip-login, password=your-noip-password
myserver.ddns.net

這樣一來，IP 從 54.201.13.7 變成 3.88.42.190 之後，等各地的 DNS 快取過期，用 myserver.ddns.net 就又能連到這台機器。

已經有自己的網域了？ 如果網域的 DNS 服務商沒有提供更新用的 API，client 就沒辦法直接更新它，例如 Squarespace Domains 接手 Google Domains 之後，就拿掉了原本的 dynamic DNS 功能。這時可以先申請一個免費的 DDNS hostname，再用一筆 CNAME 接過去，設定一次之後就不用再動。

your.domain.com  ──CNAME──►  myserver.ddns.net  ──(DDNS 隨時更新)──►  現在的 IP

不過 DDNS 現在能省的錢很少。 它以前是比較便宜的選項，因為它用的自動 IP 不用錢。2024 年改制之後，instance 開著的時候，這個 IP 跟 Elastic IP 一樣每小時 0.005 美元。現在只有 instance stop 的那幾個小時還能省，因為自動 IP 在 stop 時就被收回、不計費，而 Elastic IP 不管有沒有 attach 都照樣計費。如果每晚 stop 12 小時，一個月大約省 1.8 美元。要省下這 1.8 美元，就得在 instance 上一直維護一支 DDNS client。

換成 IPv6 呢

EC2 文件寫明，instance stop 再 start 之後，IPv6 位址會保留，要到 terminate 才會釋放。VPC 價目頁上計費的也只有 public IPv4，沒有 IPv6 這一項。所以只要 instance 有 IPv6 位址，設一筆 AAAA record 指過去，重開機之後照樣連得到。

不過 VPC 跟 subnet 都要先 associate 一個 IPv6 CIDR，instance 才會拿到 IPv6 位址。route table 也要加一條 ::/0 → igw，security group 要開放 IPv6 的來源。

而且如果使用者的網路只有 IPv4，就連不到只有 IPv6 位址的 instance。為了這些使用者留著 public IPv4 的話，那個 IPv4 一樣每小時計費，stop 再 start 也一樣會換。

Route 53 該用 A record 還是 alias

A record 把名字對到一個固定的 IP（app.mysite.com → 54.201.13.7）。Route 53 的 alias 則是把名字對到一個 AWS 資源（ELB、CloudFront），資源背後的 IP 變了，Route 53 會自己跟著更新（alias 的目標只能是 AWS 資源，不包括單獨一台 EC2）。

所以用 Elastic IP 的話，設一般的 A record 就好，因為 IP 不會變。單獨一台 EC2 不能當 alias 的目標，只能用 A record 指向它的 IP，這也是它需要固定 IP 的原因。如果前面有 ELB，或是用 VPC origin 接到 EC2 的 CloudFront，就把網域 alias 到它們，Elastic IP 可以整個拿掉，IP 交給 AWS 追蹤。

該選哪一種

2024 年起每個 public IP 都計費。DDNS 跟 Elastic IP 只在 instance stop 的時候價格有差，就算每晚 stop 12 小時，一個月也只差 1.8 美元左右，所以在這兩種之間，價格不太會影響選擇。

  • Elastic IP：設定一次就不用再管，適合正式的服務。
  • ELB：把網域 alias 到 ELB，IP 變了由 AWS 追蹤，維運的人完全不用管 IP，但 ELB 本身也要另外計費。
  • DDNS：要一直維護一支 client，比另外兩種麻煩。如果是常常 stop 的個人實驗機，為了 stop 那幾個小時省下的錢，多顧一支 client 也許還划得來。
  • IPv6：位址不會換，也不用付 IP 的錢，但只有網路上有 IPv6 的使用者連得到。
