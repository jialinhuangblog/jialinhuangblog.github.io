加了 use client，server 還是會先 render 一次

nextjsreactssr

直接開網址的時候，加了 use client 的 component 還是會先在 server 上 render 一次。靜態頁在 next build 的時候 render，動態頁在每次 request 的時候 render。

如果檔案開頭寫了 use client，Next.js 會把這個檔案連同它 import 的東西一起打包進 client bundle。client bundle 就是送到瀏覽器的 JavaScript。Server Component 的程式碼則留在 server，不會送到瀏覽器。瀏覽器拿到 server render 好的 HTML 以後執行 client bundle，把事件處理函式接到現成的 HTML 上，這一步叫 hydration。

如果是在站內點連結切頁，server 只回傳 RSC Payload，不產出 HTML，所以這個 component 只在瀏覽器裡 render。RSC Payload 是 Server Component render 完之後序列化的結果，裡面有 Server Component 的輸出、Client Component 該放在哪裡，以及要載入哪些 JavaScript 檔。

14.2（2024 年 4 月）起，用 webpack 做正式 build 時，experimental.optimizeServerReact 預設打開。它會把 server bundle 裡的 useEffect 呼叫連同 dependency array 一起拿掉，所以 prerender 的時候根本不會碰到 [window]。next dev 跟 Turbopack build 不會拿掉這個呼叫。為了確認是這個設定造成的，在 14.2 跟 15.5 把它關掉重跑，build 就出錯了。反過來在 14.1 把它打開，build 就過了。

這個設定不會把每種寫法的 useEffect 都拿掉：

  • import { useEffect } from 'react'：會看 dependency array。裡面有函式呼叫的話，例如 [getSize()]，它會保留整個 useEffect，因為那個函式可能有副作用。保留下來的 getSize() 在 prerender 時讀 window.innerWidth，server 上沒有 window，所以 build 出錯。
  • import React from 'react' 再寫 React.useEffect(...)：不看 dependency array，一律拿掉。所以就算寫 [getSize()]，build 也會過。
  • import * as React from 'react' 再寫 React.useEffect(...)：認不出這是 useEffect，整個保留。所以連 [window] 都會讓 build 出錯。

14.2.0、14.2.35、15.0.8、15.3.9、15.5.12 這五版量到的結果都跟上面一樣。規則寫在 optimize_server_react 的原始碼裡（文末參考有連結）。

中間發生了什麼

直接開網址的時候，一個 use client 的 component 會 render 兩次：

  1. Server：Node.js 執行 render function，產出 HTML。useState 的 initializer 會跑。Node.js 也會對 dependency array 求值，因為它是 useEffect(...) 這個呼叫的參數，而這個呼叫就寫在 render function 裡。但是 useEffect 的 callback 不會跑。React 文件寫明 Effect 只在 client 執行，server render 的時候不跑。
  2. 瀏覽器：瀏覽器先把 HTML 顯示出來。接著 React 做 hydration，把事件處理函式綁到這份 HTML 上，之後呼叫 setState 才會更新畫面。hydration 完成以後，useEffect 的 callback 才開始跑。

[window] 這個陣列是在第 1 步求值的。Node.js 裡沒有 window，執行到這裡就丟出 ReferenceError。

而 () => { console.log(window.scrollX) } 在第 1 步只是一個函式定義。Node.js 建立了這個函式，但不會呼叫它，要到第 2 步才會執行。

window 可以放在哪裡

位置server 會執行嗎window 安全嗎
module 最外層的變數會不安全
useState 的 initializer會不安全
useEffect 的 dependency array會不安全
useEffect 的 callback不會安全
事件處理函式不會安全

dependency array 那一列寫「會」，是因為 server render 執行 component function 的時候，useEffect(...) 這個呼叫的參數會先算出來，[window] 也包含在內。不過 Next.js 14.2 到 15.5 的預設 next build 會在編譯階段就把 useEffect(() => {}, [window]) 這種呼叫拿掉，server render 時已經沒有這一行，所以這幾版 build 才會過。

放在最外層還有一個辦法：

對一個沒宣告過的變數用 typeof，會回傳 "undefined"，不會丟錯。這是 JavaScript 的規則，跟 React 無關。

不過 isBrowser 不能拿來決定要 render 什麼。假設寫了 {isBrowser ? <A /> : <B />}，server 上 isBrowser 是 false，render 出 B；瀏覽器第一次 render 時它是 true，render 出 A。兩邊的結果不一樣，hydration 就會報 mismatch，因為 React 要求 server 的 HTML 跟瀏覽器第一次 render 的結果一致。如果被呼叫的函式不會改變 render 出來的內容，拿 isBrowser 決定要不要呼叫它就沒問題，例如 if (isBrowser) console.log(window.location.href)。server 上 isBrowser 是 false，console.log 不會被呼叫；瀏覽器上會呼叫，但只是印出一行 log。因為兩邊 render 出來的 HTML 一樣，所以不會有 mismatch。

要是某個 component 根本沒辦法在 server 上 render，Next.js 可以讓它跳過 server render，做法是 next/dynamic 加上 { ssr: false }。這個選項只能寫在 Client Component 裡，寫在 Server Component 裡會報錯。

所以 use client 到底是什麼意思

use client 把這個檔案跟它 import 的東西放進 client bundle，送到瀏覽器。直接開網址的時候，瀏覽器用這份 JavaScript 去 hydrate server 產出的 HTML。站內點連結切頁的時候沒有 HTML，component 直接在瀏覽器裡 render。

Effect 的 callback（useEffect，useLayoutEffect 也一樣）跟事件處理函式，在 server 上一律不跑。直接開網址、又沒有用 ssr: false 的時候，component 的 function body 會先在 server 上跑一遍，寫在裡面的 useState initializer 跟 dependency array 也會跟著求值。next dev 每次都會出這個錯；next build 會不會出，看 Next.js 的版本（見上面的表）。
